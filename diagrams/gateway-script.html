Chapter 5 · Tools + Gateway / Identity

Gateway Script

1 · Why Gateway exists

"Let's say I'm using LangGraph to build my agents, and I already have some existing services in AWS — say an Orders Lambda that can look up an order or cancel one."

"Now I want to expose these capabilities to my agents using MCP."

"I can absolutely build my own MCP server: register my tools, expose tools/list so agents can discover them, handle tools/call so they can invoke them, connect those calls to my Lambdas, secure the endpoint — and then I still have to host that MCP server somewhere, maybe ECS or Lambda, and operate it. And on the other side, each of my agents needs an MCP client wired in to talk to it."

"Or I need something to manage that MCP layer for me. That's where AgentCore Gateway comes in."

2 · What Gateway gives me

"So instead of building and operating that MCP server myself, Gateway gives me a managed MCP endpoint. I register my existing services as targets behind the Gateway, describe the tools they expose, and my agents access those tools through MCP."

"Let's look at a simple example."

3 · The backend

"I've built a very simple Order Helper. The agent can look up an order and calculate how much refund the customer should receive."

"This is my backend — just a Lambda with some hardcoded orders. Nothing interesting here; in a real application this would call my order system."

4 · The tool schema

"Now I need to tell Gateway what capability this Lambda exposes. I've defined a tool called get_order — a description, and one input: order_id."

"The description matters: it's what the model uses to understand what this tool does."

order_tool_schema.json — highlight ONLY: name · description · inputSchema.order_id. Move immediately.

5 · Register it

"Then in my Gateway configuration, I register the Lambda as a target."

"So now Gateway knows two things: here's my implementation — the Lambda — and here's how that capability should be exposed as a tool."

agentcore.json — highlight: protocolType MCP · target order-lookup → Lambda ARN + tool schema

6 · The agent

"Now look at my agent. I've configured the AgentCore Gateway here. But notice what's missing."

"There is no get_order tool defined anywhere in my agent. My agent knows about the Gateway. The Gateway knows about the tools."

"And notice the second thing that's missing: there's no MCP client code either. This one line asks the platform's agent loop to be the MCP client on my behalf — connect to the gateway, authenticate with IAM, discover, call."

"The agent has the phone number. It doesn't have the menu."

"At session start, it asks — MCP's tools/list — and the menu comes back: order-lookup___get_order."

7 · Demo

"Let's see if this actually works. — Can I get a refund for order 123?"

"So the agent called get_order through the Gateway. My Lambda returned the order — $48, purchased five days ago — and the agent used its Code Interpreter to calculate the refund. Within 30 days: full $48 back."
