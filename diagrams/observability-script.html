Chapter 6 · Observability

Observability Script

1 · The question

"In the memory video, my barista remembered a customer's usual. It worked. But with agents, I didn't write the steps — the model decided, at runtime, what to look up and which tools to call. So: what did my agent actually do? The answer isn't in my code. AgentCore's answer: every call is recorded — logs, traces, and metrics — by default."

camera

2 · How to enable

"Here's the entire setup, as a staircase. Once per account: enable Transaction Search in CloudWatch — one page, a minute, 1% trace indexing is free. Once per agent: nothing — if the CLI scaffolded your project, this one line in requirements.txt is the whole thing. Per call: nothing. It just records."

console: Transaction Search settings (10s) → flash requirements.txt line aws-opentelemetry-distro → done. Account: one step. Agent: zero. Call: zero.

3 · A live session

"This is the GenAI Observability dashboard in CloudWatch. Agents View — all my agents, the harnesses and the barista, which is my own LangGraph code; same telemetry either way. Sessions View — every conversation. Here's one from this morning: a customer saying 'I'll have the usual.' Let's open its trace."

console: Agents View → barista → Sessions View → today's session → Trace View. Keep moving until the trace is open.

4 · The spans

"The whole run, as a timeline. The request at the front door — POST /invocations. RetrieveMemoryRecords — the agent reading this customer's notes. My LangGraph graph, by name. The model turns, with token counts. The make_drink tool. And CreateEvent at the end — the conversation written back to memory."

"That's the entire architecture from the memory video, as a recording of it actually happening — and I wrote none of this telemetry. The platform instrumented my code, my framework, even my memory calls, automatically."

the trace trajectory/timeline. Walk spans top to bottom — the money shot.

5 · Built-in metrics

"And underneath the traces, metrics — provided, not built: invocations, latency, errors, token usage, sessions, per agent. Sliced finer than you'd expect — here's tool latency, per tool: how long the code interpreter takes versus the gateway lookup. And it's not just agents — memory, gateway, the built-in tools, identity: every AgentCore service publishes its own metrics. It goes deep; the catalog's in the docs."

console: Metrics → bedrock-agentcore namespace → one per-ToolName latency chart. One chart, one breath for the rest. (Optional one-liner: it's all standard OTel + CloudWatch — dashboards or Grafana/Datadog if that's your stack.)

6 · Close

"So now I can see everything my agent did — every tool call, every token, every second. But here's what this dashboard can't tell me: whether the answer was any good. The agent can be fast, cheap, traced end to end — and wrong. Putting a number on 'good' — that's the last video."

camera. Hard stop.
