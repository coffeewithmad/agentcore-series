Chapter 6 · Observability — reading a trace

Trace Anatomy

One real invoke — session 0f1fabd7…, "I'll have the usual" — 19 spans, 2.3 seconds, drawn to scale from the actual telemetry and compressed for reading: the ten repeated memory writes share one row, and each doubled model span is drawn once. The console shows every span as its own bar — more rows, same story.

POST /invocations

The front door — and the root span. The SDK's HTTP server receiving the request. Every other span is its descendant; its duration (2,287ms) is what the caller experienced. When the dashboard shows "a trace," this is the top of it.

Bedrock AgentCore.RetrieveMemoryRecords

Long-term memory being read — this is load_usual searching the customer's namespace for their distilled notes. 350ms, before the graph even starts. If "the usual" ever stops working, this span is the first place to look.

invoke_agent LangGraph

Your graph, as one span. The framework instrumentation wraps the whole graph.invoke() call — everything your agent "did" nests inside this bar. Its name is literally your framework's.

Bedrock AgentCore.ListEvents

The tape being restored. First thing inside the graph: the checkpointer asks memory for this thread's prior state. 44ms. New session, so it comes back nearly empty.

chat claude-haiku (two of them)

The model turns — where the time and money go. Turn one (750ms, 630 tokens in / 56 out): the model reads the prompt plus the injected usual and decides to call the tool. Turn two (869ms, 710 in / 32 out): it sees the tool result and writes the reply. Token counts on these spans are the cost of the call, per turn.

execute_tool make_drink

The tool itself. One millisecond — because ours is a stub returning a string. With a real backend this bar is where your API's latency shows up, separated from the model's.

Bedrock AgentCore.CreateEvent ×10

The tape being written. The checkpointer persists state after each step of the graph — that's most of these — plus log_exchange writing the transcript for the distiller at the end. Ten small writes, ~80–135ms each, overlapping the run. Chatty by design: that's what durable conversation state costs.

Why some chat spans appear doubled

Two instrumentation layers both record the model call: the framework layer (LangChain's view of the turn) wrapping the botocore layer (the raw Bedrock API call). Nested, near-identical duration — not a double charge, just two witnesses to one event. Normal; read the outer one.
