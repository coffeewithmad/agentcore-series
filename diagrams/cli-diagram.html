One tool, both paths

The AgentCore CLI drives the whole lifecycle — scaffold, run locally, deploy, invoke — for a config-based harness or a code-based agent alike. Everything here verified hands-on with @aws/agentcore 0.29.0, Sep 21 2026.

The lifecycle crosses one boundary

dev stays on your laptop, deploy creates the cloud twin, invoke talks to it. One honest wrinkle: even local dev calls Bedrock for the model.

The starter agent is real

The generated agent is Claude Sonnet 4.5 on Bedrock with tool calling, streaming, and per-session history — plus an example MCP client pre-wired to mcp.exa.ai (Exa web search, no auth). That last one means demo prompts that trigger search leave AWS for a third party — fine, as long as you say it.

Prototype tool, not delivery pipeline

deploy runs CDK from your laptop with your credentials — perfect for the dev loop, not how a team ships. Production keeps the app/ code verbatim and replaces the deploy mechanism with CI/CD (their own CDK or Terraform). You keep the agent; you swap the launcher.
