Chapter 4 · Memory

The Memory Boundary

One diagram, told twice. Cut 1: everything memory asks of you when you build it yourself with LangGraph. Cut 2: the same boxes — and the responsibility boundary moving.

Cut 1 — What am I managing today?

The DIY landscape. Every box on this figure is yours to build, configure, and operate.

Say — short-term"For short-term memory I have my LangGraph state and thread id. I need a production checkpointer. I need to manage the context window. And I have APIs for inspecting those checkpoints."

Say — long-term"Long-term memory is what your agent carries across sessions. Not the transcripts — the things worth remembering: preferences, facts, past decisions. So: a store organized by namespace, a decision about what's worth keeping, and a way to retrieve it later — typically semantic search."

Say — the zoom"And notice: long-term memory isn't just storage. If a customer says 'I normally drink an oat-milk latte, extra hot,' I don't want to replay the conversation — I want the useful fact: this customer prefers an oat-milk latte, extra hot."

Cut 2 — What changes with AgentCore?

The same boxes. Watch the responsibility boundary move — and what refuses to move.

stays yours AgentCore manages shared — straddles the boundary

Say — the move"Now let's see what changes when I add AgentCore Memory. Persistence — both databases — extraction, and retrieval move across. Moving the checkpointer is one line of code; the extraction policy is ten lines of JSON. And notice what does not move: context management. AgentCore remembers; what the model sees each turn is still my job."

Say — the amber"The amber boxes are shared. Inspecting checkpoints: my LangGraph code doesn't change — same get_state_history, same config — and I get AgentCore's APIs and console as a second window. And long-term memory is a partnership: I write the transcript in; AWS distills the notes — in the background, asynchronously."

The config that moves the boundary

Cut 2's "show the configuration briefly" beat — this block is what the choice becomes.

agentcore/agentcore.json — the whole long-term memory policy
"memories": [{
  "name": "barista_mem",
  "eventExpiryDuration": 30,
  "strategies": [{
    "type": "USER_PREFERENCE",
    "name": "usual_order",
    "description": "Extract each customer's usual
                    coffee order from conversations",
    "namespaces": ["/customers/{actorId}"]
  }]
}]
Say "Ten lines. The strategy type is the editorial policy — what's worth remembering. The namespace is the filing scheme — one drawer per customer. Behind this block stands the entire right-hand column: the store, the extraction pipeline, the semantic index."
The money shot — freeze here

"My LangGraph agent hasn't disappeared. It still owns the workflow, the state, and what goes into the model. What I've moved to AgentCore is the infrastructure around memory — and, for long-term memory, the distilling and retrieval of useful facts."
