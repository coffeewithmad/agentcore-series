Chapter 3 · The Harness

The Harness Dev Loop

For a harness, dev, deploy, and invoke all end up at the same deployed agent — because there is nothing to run on your laptop. The loop, the tools, and the model live AWS-side; the CLI just gives you three doors into them.

The whole path

Wizard choice → declaration → dev → working agent. Four stages you can point at while talking.

Say over 1"The wizard gives you one real choice: write the agent in a framework — or just describe it. The Harness is literally the default."

Say over 2"Then three decisions: which model — Sonnet on Bedrock; which tools — I take the built-in browser and code interpreter; and memory — disabled is the default, but I select managed: AgentCore owns the conversation memory for me. All of it lands in two files. Zero code."

Say over 3"dev deploys first — a harness only exists in the cloud — then opens a local cockpit to talk to it."

Say over 4"Every message runs AWS-side: the model reasons, the browser gathers, the code interpreter compares, memory keeps the thread — out comes the report."

The two files

The entire agent, exactly as deployed on 2026-09-26. Highlighted values are the choices from stage 2.

harness.json — the spec sheet
{
  "name": "ResearchAgent",
  "model": {
    "provider": "bedrock",
    "modelId": "us.anthropic.claude-sonnet-4-5…"
  },
  "tools": [
    { "type": "agentcore_browser" },
    { "type": "agentcore_code_interpreter" }
  ],
  "memory": { "mode": "managed" }
}
Say"This file is the spec sheet: which brain, what it can do, whether it remembers. Four fields. The two tools are built-ins — AWS runs them, not me. And memory is one word: managed."
system-prompt.md — the job description
You are a research agent.

Given a research goal, investigate the topic
using the tools available to you.
The user's message IS the research goal —
never ask them to restate or clarify it.

Use the browser to find current information.
Go directly to authoritative pages…
Budget: at most 5 browser actions per goal.
If a browser action fails twice, stop browsing
and continue with what you already know…

Use the code interpreter when analysis or
calculations are useful.

Always end your turn with the report —
a concise summary of what you found.
Never end with a question.
Say"And this file is the job description — who the agent is, and its working rules. Notice they read like instructions to a junior researcher: use good sources, budget your browsing, and always come back with the report. Prompt engineering IS the programming model here."

Two territories, three doors

Where each command actually lands — nothing executes on the laptop.

agentcore dev

Deploys, then hands you a cockpit

Synthesizes the CDK app, creates or updates the stack, then serves the inspector on localhost. That's the whole trick: for a harness, dev = deploy + inspector.

Use it as your main loop while shaping the agent — chat, watch traces, iterate on the prompt.

agentcore deploy

The same deployment, minus the cockpit

The identical CDK synth and stack update, with no dev server. Nothing extra to run after dev — it's the same stack.

Use it to push a config change without the inspector, or from CI — this is the production path.

agentcore invoke

A caller, not a deployer

Sends one prompt to the already-deployed harness from the terminal. Deploys nothing, changes nothing.

Use it for smoke tests and scripting. Harness quirk: it prints only the first assistant turn — the full tool-using run shows in traces.

The edit gotcha (hit live, 2026-09-26): the running dev server does not hot-sync harness.json edits to AWS — the declaration is baked in at deploy time. After editing, restart dev (quick stack update) or run deploy. Why the docs still say "local hot-reload": that's the code-agent path, where dev builds and runs a container on your machine. A harness has no code to run — so its dev loop goes through the cloud.

So, for today

dev alone is enough: restart it to pick up the Sonnet 4.5 edit, then chat in the inspector. deploy is optional (same push without the cockpit) and invoke is optional (terminal smoke test). Whichever door you use, you're talking to the same deployed harness.

Script essentials — the six beats

~5 minutes total · every line below was verified live on 2026-09-26 with the ResearchAgent harness.

Intro~0:30

"This is a working AI agent, deployed on AWS. It reasons, it browses the web, it writes and runs code in a sandbox. And here is all of it — two files. Zero lines of agent code."

Setup~1:00

"You don't write an agent — you declare one. The config names a model, its tools — here, the built-in browser and code interpreter — and memory, one line. The prompt file says what the agent is. AgentCore assembles the rest: the loop, tool execution, streaming, retries."

Show the four fields of harness.json, then the prompt. Run agentcore create mentioned in passing — the scaffold, not the concept.

Launch~0:45

"One command: dev. And watch what it does first — it deploys. A harness only exists in the cloud; there's nothing to run on my laptop. So dev pushes the declaration to AWS, then opens a local cockpit to talk to it."

Show the terminal deploy phase (CloudFormation progress), then the inspector connecting. Run agentcore dev

Demo~1:30

"Let's give it a real research goal — and just watch the loop work: browser rounds to gather facts, the code interpreter to build the comparison, then a report. We wrote none of this code, and none of it ran on my machine."

Show the inspector chat; expand the tools-used strip as rounds land. Prompt "Research three open-weight language models that can realistically run on a single GPU. Compare their model size, context window, hardware requirements, and license. Produce a concise report explaining the trade-offs."

Reality check output varies per take (different model trios are normal); a failed page-load mid-run is fine — the agent pivots and still reports. Record a real take.

Two cmds~0:30

"You might wonder — dev just deployed, so what's deploy for? Deploy is a step; dev is a loop that begins with that step. Deploy ships it — dev ships it and pulls up a chair. On the code path, dev means run it here. A harness has no 'here'."

Show the dev-loop diagram above. Run agentcore deploy --diff → "There were no differences" — the on-camera proof that dev already shipped everything.

Close~0:45

"That's the Harness: the fastest path from an idea to a deployed, tool-using agent — a config file and a prompt. One agent with a clear job is its home turf.
