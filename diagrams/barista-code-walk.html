1 · The agent barista_graph.py · 17–25

"Meet my Barista. It's Haiku on Bedrock — line 17 — plus a job description, lines 20 to 25: take coffee orders, keep it short, confirm warmly. And one more sentence: if a customer asks for 'the usual' and you've been told their usual, make it — if not, cheerfully ask. Hold onto that line. It's the hook the whole memory story hangs on."

2 · The tool barista_graph.py · 33–36 barista_graph.py · 39

"It has exactly one tool: make_drink, lines 33 to 36 — it rings up an order and says it'll be ready at the bar. And line 39, bind_tools, is what tells the model this tool exists and what it takes. That's it — the model now knows it can make drinks."

3 · A question becomes a drink barista_graph.py · 42–48 barista_graph.py · 55–57

"So what happens when you say 'a large latte, please'? The barista node — lines 42 to 48 — hands the conversation to the model, and the model doesn't just reply: it emits a tool call. Line 56, tools_condition, sees that and routes to the tool node. The tool runs — the drink is rung up — and line 57 loops the result back into the barista, which now answers: 'coming right up.' Ask → tool → answer. That loop is the whole agent."

4 · State barista_graph.py · 28–30

"Now — where does memory live? Start with State, lines 28 to 30. Two fields. messages — the conversation so far. I think of it as the tape. And usual — one string carrying what we know about this customer long-term. The note. The whole video is the story of these two fields."

5 · Short-term — the tape main.py · 22–28 barista_graph.py · 58 main.py · 78

"Short-term memory is the checkpointer. Look at main.py, lines 22 to 28 — an if/else. Line 24 is the AgentCore line: AgentCoreMemorySaver, one line, pointing at a managed memory resource — no database of mine anywhere. Line 28 is the local fallback for offline runs. The graph takes whichever it's given — line 58, compile(checkpointer=…) — and line 78 picks which tape we're on: the thread id. Same thread, the tape continues. New thread, blank tape."

Green chips = main.py, terracotta = barista_graph.py — the file boundary IS the AgentCore boundary.

6 · Long-term — reading the note main.py · 34–50 barista_graph.py · 44–45

"Long-term memory is a search, not a lookup. load_usual, lines 34 to 50: line 39 calls retrieve_memory_records — semantic search — and line 41 says where: /customers/ and the customer's id. One drawer per customer. Whatever comes back rides into the graph, and back in the node — lines 44 and 45 — it's injected into the prompt: 'this returning customer's usual: …' That's the moment the note meets the model — and the moment that 'usual' sentence from beat one pays off."

7 · Long-term — writing, and the policy main.py · 53–69 agentcore.json · memories

"And how do notes get made? Look how little I do — log_exchange, lines 53 to 69: line 58 writes the raw exchange as an event. That's all my code does. I write the transcript; AWS writes the memory. The distilling is configured, not coded — ten lines in agentcore.json: a USER_PREFERENCE strategy, filed under /customers/{actorId} — the very same namespace line 41 reads from. Config on one end, a search on the other, and the service does the remembering in between."
